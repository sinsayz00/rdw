주제 2 · 1안

AI는 웹사이트를 서로 비슷하게 만드는가

생성형 AI 기반 웹 UI 제작의 구현 제약 완화와 결과물 동질화에 관한 연구 — 일정 제약 조건을 중심으로

문제

사람은 바쁘면 같은 디자인을 다시 쓰고, AI는 업종이 달라도 비슷하게 만든다.

질문

AI는 “바빠서 생기는 획일화”를 줄일까, “AI만의 획일화”를 새로 만들까?

방법

같은 요청서로 만든 AI 결과물과 우리 회사 작업물을 비교한다.
수정 기회를 1번(촉박)과 5번(여유)으로 나눠 일정의 영향도 본다.

사람 · 바쁠 때: 같은 틀에 색만 바꿈

AI · 업종이 달라도: 같은 모양으로 모임

예시 그림 · 실제 결과는 실험으로 확인

예상 결론

AI는 일정 때문에 생기던 획일화는 줄이지만, AI 특유의 획일화를 새로 만든다.

(주)이에이지 · 연구 주제 발표

07

사람도 바쁘면 같은 틀에 색만 바꿔 씁니다. AI는 업종이 달라도 보라색 그라데이션과 카드 세 개 같은 비슷한 모양으로 모이는 경향이 있습니다. 같은 요청서로 AI 결과물을 만들고, 우리 회사 작업물과 프로그램으로 비교해서 어느 쪽 획일화가 더 강한지 확인합니다. 결론은 실험 전의 가설입니다.

주제 3 · 2안

디자인을 데이터로 넘기면 AI가 끝까지 지킬까

디자인 토큰 기반 지시가 생성형 AI 웹 UI의 디자인 의도 보존과 코드 일관성에 미치는 영향

문제

AI에게 시안을 주고 코딩을 시키면,
수정할수록 색과 간격이 틀어지고 코드도 페이지마다 값이 달라진다.

디자인 토큰

색·글자 크기·간격 같은 디자인 값에 이름을 붙여 정리한 데이터. 

  • 예: 주색 = #1F3A5F

방법

같은 디자인을 네 가지 방법으로 준다.

  • 없음 · 시안 이미지 · 토큰 · 토큰+부품 설명. 
  • 결과물을 만들어 4번씩 수정하고 프로그램으로 잰다.

디자인 토큰은 색이나 글자 크기 같은 디자인 값에 이름을 붙여 데이터로 정리한 것입니다. 지금은 디자이너가 시안 이미지를 넘기는데, 이를 토큰으로 넘기면 AI가 수정을 거쳐도 디자인을 더 잘 지키는지 확인합니다. 오른쪽 그림은 이해를 돕기 위한 예시이고, 실제 결과는 실험으로 확인합니다.

(주)이에이지 · 연구 주제 발표

09

세 가지만 봅니다. 화면이 디자인대로 보이는지, 코드에서 같은 것을 같게 썼는지, 누구나 쓸 수 있는지입니다. (질문이 나오면) 화면은 브라우저에 실제 적용된 값을 뽑아 디자인 값과 비교하고, 색은 사람 눈 기준의 색 차이로 판단합니다. 코드는 라이브러리를 뺀 직접 작성한 CSS에서 지표 19종을 세고, 사이트끼리는 클래스 이름을 빼고 CSS 선언과 HTML 뼈대로 재사용을 찾습니다. 품질은 W3C의 Nu Html Checker, axe-core, Lighthouse로 자동 검사하고 일부는 NIA의 OpenWAX와 키보드로 직접 확인합니다. 통과율 대신 위반 건수와 심각도로 비교합니다.
